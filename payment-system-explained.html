Money — play with it, in pipeline order

The system's order is always: Kafka message → obligation → request creation → enrichment → payment call → Kafka notification. The strip shows where you are. committed = money spoken for (the active request's reservation) · confirmed = money settled · shortfall = required − committed. Only three counter moves — nothing else touches money

WhenMove
request row INSERTed (§6.8 — the only creation point)committed += amount
terminal-negative outcome (REJECTED / CANCELLED / SUPERSEDED), CAS row-count = 1committed −= amount
settlement evidence, amount EXACTLY equal (all-or-nothing contract)confirmed += amount

POST, retries, responses, timeouts: no movement. A crash mid-POST cannot desync money — the reservation just stays held. Fail-blocked, never pay-twice.
